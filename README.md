# NOMA — Совместный редактор документов

NOMA — это веб-редактор для совместной работы над документами, вдохновленный современными инструментами продуктивности.

Проект поддерживает совместное редактирование в реальном времени, работу в офлайн-режиме, автоматическое разрешение конфликтов и отображение активного присутствия пользователей.

Интерфейс был намеренно разработан так, чтобы не копировать Google Docs.

---

## Возможности

- Редактирование форматированного текста (Rich text)
- Жирный шрифт и курсив
- Заголовки H1 / H2
- Маркированные списки
- Нумерованные списки
- Отмена / повтор действий
- Совместное редактирование в реальном времени
- Синхронизация заголовка в реальном времени
- Несколько пользователей в одном документе
- Индикаторы активных пользователей
- Совместные текстовые курсоры
- Живые указатели мыши
- Офлайн-редактирование
- Автоматическое переподключение
- Разрешение конфликтов на основе CRDT
- Сохранение данных в браузере с помощью IndexedDB
- Сохранение документов на стороне сервера
- Статус подключения:
  - Подключение (Connecting)
  - Синхронизация (Syncing)
  - Синхронизировано (Synced)
  - Не в сети (Offline)

## Установка

Клонируйте репозиторий:

```bash
git clone YOUR_REPOSITORY_URL
cd noma-collaborative-editor
```

Установите зависимости:

```bash
yarn
```

---

## Запуск проекта

Приложение использует два процесса:

1. Фронтенд на Vite
2. WebSocket-сервер Yjs для совместной работы

### Запуск WebSocket-сервера

```bash
yarn ws
```

WebSocket-сервер запускается по адресу:

```text
ws://localhost:1234
```

### Запуск фронтенда

Откройте другой терминал:

```bash
yarn dev
```

Vite отобразит URL-адрес приложения, обычно это:

```text
http://localhost:5173
```

document-1

## Синхронизация в реальном времени

Синхронизация документов в реальном времени реализована с использованием Yjs и y-websocket.

Вместо того чтобы отправлять весь документ целиком и перезаписывать версию другого пользователя, Yjs использует CRDT (бесконфликтные реплицируемые типы данных).

Это позволяет нескольким пользователям редактировать один и тот же документ одновременно, сохраняя при этом все изменения.

Tiptap подключен напрямую к общему Yjs-документу.

---

## Почему Yjs?

Основные требования проекта:

- одновременное редактирование
- синхронизация без конфликтов
- офлайн-редактирование
- корректное слияние после переподключения

Простой подход, такой как замена документа на сервере последней клиентской версией, мог бы привести к тому, что пользователи перезаписывали бы изменения друг друга.

Yjs решает эту проблему с помощью модели данных CRDT.

Благодаря этому параллельные и офлайн-изменения объединяются автоматически после синхронизации.

---

## Офлайн-режим

Офлайн-сохранение реализовано с помощью `y-indexeddb`.

Yjs-документ сохраняется локально в IndexedDB браузера.

Когда WebSocket-сервер недоступен:

```text
Редактор
   ↓
 Y.Doc
   ↓
IndexedDB
```

Пользователь может продолжать редактировать документ.

Когда сервер снова становится доступен:

```text
IndexedDB / Y.Doc
        ↓
    WebSocket
        ↓
Слияние Yjs CRDT
        ↓
 Другие клиенты
        ↓
Серверное хранилище
```

Офлайн-изменения синхронизируются автоматически, не затирая изменения, сделанные другими пользователями.

---

## Присутствие пользователей (Presence)

Присутствие пользователей реализовано с помощью Yjs Awareness.

Awareness содержит временную информацию о совместной работе, такую как:

- ID пользователя
- имя пользователя
- цвет пользователя
- текстовый курсор
- выделение текста
- положение мыши

Информация о присутствии не сохраняется как часть самого документа.

---

## Сохранение документов

В проекте есть два уровня сохранения данных.

### Сохранение в браузере

IndexedDB хранит локальную копию Yjs-документа.

Она используется для:

- офлайн-редактирования
- локального восстановления
- синхронизации при переподключении

### Сохранение на сервере

WebSocket-сервер использует локальное хранилище LevelDB.

Это позволяет документам сохраняться после перезапуска сервера, а новым клиентам — загружать ранее созданные документы.

## Тестирование совместной работы в реальном времени

Запустите фронтенд и WebSocket-сервер.

Откройте один и тот же документ в двух разных браузерах:

```text
http://localhost:5173/document/1
```

Отредактируйте документ в Браузере A.

Изменения должны появиться почти мгновенно в Браузере B.

Изменения форматирования также должны синхронизироваться.

---

## Тестирование офлайн-режима

1. Запустите фронтенд.
2. Запустите WebSocket-сервер.
3. Откройте один и тот же документ в двух разных браузерах.
4. Убедитесь, что оба клиента синхронизированы.
5. Остановите WebSocket-сервер.
6. Продолжайте редактирование в офлайн-режиме.
7. Внесите разные изменения в каждом браузере.
8. Снова запустите WebSocket-сервер.
9. Оба клиента переподключатся автоматически.
10. Yjs объединит изменения.
